# Agent instructions

Static HTML/CSS/JS site for Flowers by Tavi. No build step, no package manager, no dependencies to install — just edit files directly.

See `README.md` first for the human-facing guide to common edits (prices, copy, photos, deploy). The notes below are hard constraints for automated edits.

## Hard rules

- **Never hand-edit `images/hero-bouquet.svg` or `images/story.svg`.** Both are generated by scripts in `tools/` (`gen_hero_bouquet.py`, `gen_story_bouquet.py`). To change either animation, edit the script and regenerate, e.g. `python3 tools/gen_story_bouquet.py images/story.svg`.
- **SVG animation gotcha:** if an element needs both a static `transform` (e.g. `translate(...) scale(...)`) and an animated one, put them on separate nested `<g>`s. Combining a pixel-based `transform-origin` with a `translate()` in the same `transform` on one element compounds the offset and can push the shape far outside the viewBox with no visible error — this bit `gen_story_bouquet.py` during development.
- **Don't touch `API_URL` in `js/main.js`** unless explicitly given a real API host — it's live production config, not a placeholder to guess at. The enquiry backend lives in the separate private `flowers-by-tavi-api` repo; its secrets are Vercel environment variables and must never appear in this repo.
- **The Turnstile `data-sitekey` in `index.html` is public and safe to commit.** The matching SECRET key belongs only in the API's Vercel environment — if you ever see a Turnstile secret in this repo, that is a leak.
- When renaming or adding a product in `index.html`, keep three things in sync: the `bouquet-card` block, its `data-bouquet` attribute, and the matching `<option>` in the "Which piece" dropdown inside `#path-collection`.
- This repo deploys **automatically on merge to `main`** via GitHub Pages (live at flowersbytavi.co.uk) — there is no staging environment and no CI gate. Treat a merge to `main` as instantly public.

## Local preview

```bash
python3 -m http.server 8000
```
Then open <http://localhost:8000>. Always sanity-check a change this way (or by opening `index.html` directly) before it's merged.
