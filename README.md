# Flowers by Tavi

A single-page, mobile-responsive website for Flowers by Tavi — handcrafted flower bouquets. Static HTML/CSS/JS with no build step: browse bouquets and occasions, then send an enquiry.

## Run it locally

From this folder:

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000>. (Opening `index.html` directly in a browser also works.)

## How the enquiry form delivers

Enquiries are handled by our own API, not a third-party form service. The
server lives in the private `flowers-by-tavi-api` repo and runs on Vercel;
this site posts JSON to it. It screens each submission with a honeypot,
Cloudflare Turnstile, per-IP rate limiting and server-side validation, then
emails the enquiry to flowersbytavi@outlook.com with Reply-To set to the
customer.

To change where enquiries are delivered, update `MAIL_TO` in the API
project's Vercel environment variables — no code change needed here.

If the API host ever changes, update `API_URL` at the top of `js/main.js`.

## Replace or add product photos

Product photos live in `images/` (`1.PNG`, `2.PNG`, `3.PNG`, `4.PNG`/`4.1.PNG`, `5.jpg.jpeg`/`5.1.jpg.jpeg`). To swap one out, drop the new file into `images/` and update the matching `<img src="...">` in the `#bouquets` section of `index.html`. Cards are square-cropped (`object-fit: cover`), so any photo aspect ratio works. The hero image is a real photo with its background removed (see below); the Our Story image is a generated animated illustration (see below).

Two products (Luxury Rose Box, Signature Rose Bouquet) show a 2-photo carousel. To add a second photo to any other product, wrap its `<img>` in a `<div class="card-media card-carousel" data-carousel>` with a `.carousel-track` containing both images plus the arrow/dot buttons — copy the markup from one of the existing carousel cards.

## The hero bouquet photo

The hero shows a real photo of a bouquet, `images/bouquet-cutout.webp`, floating free against the hero's blush gradient. The source photo, `images/bouquet.png`, was shot against a solid black backdrop; `tools/cutout_bouquet.py` removes that background (flood-fill from the border, plus a short list of hand-identified pockets fully enclosed by foliage that the flood-fill can't reach) and writes a transparent WebP cutout.

```bash
python3 tools/cutout_bouquet.py
```

The cutout is calibrated pixel-for-pixel for the current 1368×1150 `images/bouquet.png` — the script asserts on that size, so pointing it at a different source image needs the pocket coordinates re-derived first (see the comments in the script) before the assertion is loosened.

## The hero's decorative layer

Two kinds of ornament float behind the hero content, both non-interactive and hidden below 820px width where there's no room for them:

- **Sparkles and a drifting petal**, `images/hero-decor.svg`, generated by `tools/gen_hero_decor.py`. **Don't hand-edit the SVG** — edit the script and regenerate:

  ```bash
  python3 tools/gen_hero_decor.py images/hero-decor.svg
  ```

- **The two gold line-art corner florals** (top-left, bottom-right), `images/hero-corner-tl.webp` and `images/hero-corner-br.webp` — cut from `images/bg-item1.png` / `images/bg-item2.png` (line art on a solid black backing) via `tools/cutout_lineart.py`, which strips the black backing and writes a right-sized WebP. They're applied as CSS `background-image`s on plain `<div>`s rather than `<img>` tags, specifically so mobile browsers never fetch them once `.hero-decor-corner { display: none }` kicks in below 820px. Regenerate with:

  ```bash
  python3 tools/cutout_lineart.py images/bg-item1.png images/hero-corner-tl.webp 300
  python3 tools/cutout_lineart.py images/bg-item2.png images/hero-corner-br.webp 380
  ```

  The trailing number is the output width in pixels, chosen at roughly 2× each ornament's actual on-screen width (150px / 190px, set in `css/style.css`) for retina sharpness without oversampling. If you change those on-screen widths, update the corresponding `height` in `css/style.css` too (a `<div>` has no intrinsic size the way an `<img>` did) and re-run with a matching new output width.

## The Our Story bouquet illustration

`images/hero-bouquet.svg` is a generated animated bouquet mark — roses, peonies and a cream rose in jewel tones, wrapped in florist's paper with a gold ribbon and the Tavi monogram. It blooms open on load, then settles into a continuous sway. Despite the filename, it now lives in the Our Story section (it was moved out of the hero when the hero switched to a real photo).

**Don't hand-edit the SVG** — it is generated, and its ~350 petals are laid out arithmetically. Edit `tools/gen_hero_bouquet.py` instead and regenerate:

```bash
python3 tools/gen_hero_bouquet.py images/hero-bouquet.svg
```

The bloom layout (positions, sizes, flower type, colour family, timing) lives in the `blooms` list; colours live in `TONES`; all motion is in the `<style>` block at the bottom of `build()`.

The file is 240 KB raw but ~22 KB gzipped, which is what GitHub Pages actually serves. It is loaded via a plain `<img>` tag, which keeps its CSS scoped to the SVG and out of the page. All motion sits behind `prefers-reduced-motion: no-preference`, so visitors who ask for reduced motion get the finished bouquet with no animation at all.

If you'd rather use a real photo of Tavi in the Our Story section instead, just drop it into `images/` and update the `<img src="...">` there — no need to keep the generated illustration once you have one.

### `images/story.svg` (unused)

`images/story.svg` — a delicate gold line-art bouquet in front of a softly pulsing blush heart, generated by `tools/gen_story_bouquet.py` — was the original Our Story placeholder before `images/hero-bouquet.svg` was moved there. It isn't referenced anywhere in `index.html` any more. The file and its generator are kept in the repo per this branch's convention of not deleting superseded assets, not because they're live — no need to regenerate `story.svg` unless you're intentionally reviving it.

## Edit products, prices, and copy

Everything is plain text in `index.html`:

- **Product names, prices, descriptions, and options** — the `bouquet-card` blocks in the "Our Collection" section. If you rename a product, also update its `data-bouquet` attribute and the matching `<option>` in the "Which piece" dropdown inside `#path-collection`.
- **Contact details** — email, phone, and Instagram links in the footer.
- **Announcement bar, story text, thank-you message** — edit in place.

## Deploy

Any static host works. Easiest options:

- **Netlify**: drag this folder onto <https://app.netlify.com/drop>
- **GitHub Pages**: push this repo to GitHub → Settings → Pages → deploy from branch

No build step or configuration needed.
